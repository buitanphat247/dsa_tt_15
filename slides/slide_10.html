PHẦN II: CẤU TRÚC TRIE (PREFIX TREE)

3 Chiến Lược Lưu Nút Con Trong Trie: Fixed Array vs Hash Map vs Vector

1. Fixed Array children[26]

$O(1)$ Direct
26 con trỏ $\times$ 8B = 208B riêng cho mảng trên 64-bit:
[ 'a' ➔ Ptr | null | null | ... x25 null ]
  • Ưu điểm: Tra cứu cực nhanh $O(1)$ trực tiếp qua chỉ số mảng c - 'a'.
  • Nhược điểm: Lãng phí khi node có ít nhánh (ví dụ 1/26 child $\to \sim 96\%$ con trỏ là null); chỉ cố định cho alphabet nhỏ (a-z).
  • Phù hợp: Lập trình thi đấu, ứng dụng xác định trước chỉ dùng bảng chữ cái tiếng Anh a-z.

2. Hash Map unordered_map

Alphabet Lớn
Overhead: bucket array + hash node + allocator:
{ 'a': Ptr1, 'd': Ptr2, 'x': Ptr3 }
  • Ưu điểm: Tra cứu trung bình $O(1)$; linh hoạt với tập ký tự lớn/Unicode nếu dùng kiểu khóa phù hợp (char32_t, string).
  • Nhược điểm: Overhead cao (mảng bucket, cấp phát động phân mảnh, hằng số thời gian hàm băm).
  • Phù hợp: Cần tra cứu trung bình $O(1)$ với alphabet lớn hoặc không cố định trước.

3. Sorted std::vector

Gọn Bộ Nhớ
24B cho object vector + bộ nhớ cho child thực tế:
[ ('a', Ptr), ('r', Ptr), ('t', Ptr) ]
  • Ưu điểm: Tiết kiệm bộ nhớ nhất khi node có ít nhánh; mảng liên tục tận dụng tốt Cache Locality.
  • Nhược điểm: Tra cứu $O(\log k)$ qua Binary Search; chèn phần tử tốn $O(k)$ do dịch mảng.
  • Phù hợp: Từ điển lớn cần tối ưu dung lượng RAM trên thiết bị tài nguyên thấp (Mobile/Embedded).
Tiêu Chí Đánh Đổi Fixed Array children[26] Hash Map unordered_map Sorted std::vector
Độ Phức Tạp Tra Cứu $O(1)$ trực tiếp (chỉ số mảng) $O(1)$ trung bình (kèm hàm băm) $O(\log k)$ (Binary Search)
Chi Phí Bộ Nhớ Nút $208\text{B}$ riêng cho mảng con trỏ (64-bit) Cao, phụ thuộc số bucket/phần tử Overhead nhỏ ($24\text{B}$) + $O(k)$ cho $k$ child
Khả Năng Mở Rộng Tập Ký Tự Cố định alphabet nhỏ (a-z) Linh hoạt với alphabet lớn / Unicode Linh hoạt theo kiểu khóa (Key)
Tính Cục Bộ Cache (Cache Locality) Kém (đa số con trỏ là null) Kém (phân mảnh heap do node băm) Rất tốt (mảng phần tử liên tục)
Kính thưa Thầy và các bạn, việc lựa chọn cấu trúc lưu trữ con trong Trie phụ thuộc vào đặc thù bài toán: 1. Fixed Array children[26]: Cho tốc độ O(1) nhanh nhất qua phép tính c - 'a', nhưng tốn 208B mỗi nút (lãng phí ~96% RAM khi node chỉ có 1 con). 2. unordered_map: Giúp hỗ trợ tập ký tự lớn/Unicode khi dùng kiểu khóa phù hợp, tra cứu O(1) trung bình nhưng tốn overhead mảng bucket và phân mảnh heap. 3. Sorted vector: Giải pháp tiết kiệm bộ nhớ nhất cho node ít nhánh (chỉ 24B overhead cơ sở), mảng liên tục tận dụng tối đa CPU Cache Locality.
