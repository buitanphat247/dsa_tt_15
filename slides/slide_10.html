Phân Tích Đánh Đổi Child Container: Fixed Array vs Hash Map vs Vector

Fixed Array [26]

Nhanh Nhất
RAM mỗi Nút: 26 × 8B = 208 Bytes cố định.
'a' null null ... null (x25)
  • Tốc độ: $O(1)$ cực tốc qua offset c - 'a'.
  • Lãng phí: Trống ~95% con trỏ (chứa null).
  • Nhược điểm: Chỉ hỗ trợ 26 ký tự ASCII Anh.

Hash Map unordered_map

Đa Ngôn Ngữ
RAM mỗi Nút: Co giãn linh hoạt theo số con.
'a' ➔ Ptr1 'd' ➔ Ptr2
  • Tốc độ: $O(1)$ trung bình (Chi phí Hash function).
  • Lợi thế: Hỗ trợ Unicode, Tiếng Việt UTF-8.
  • Overhead: Tốn bộ nhớ duy trì bảng Hash Table.

Sorted std::vector

RAM Tối Ưu
RAM mỗi Nút: Mảng liên tục (Contiguous RAM).
['a', Ptr] ['r', Ptr]
  • Bộ nhớ: Cực kỳ gọn nhẹ, Cache Locality tối ưu.
  • Tốc độ: $O(\log |\Sigma|)$ dùng std::lower_bound.
  • Lợi thế: Duyệt danh sách con theo thứ tự ABC.
Tiêu Chí So Sánh Fixed Array [26] Hash Map unordered_map Sorted std::vector
Độ Phức Tạp Tra Cứu $O(1)$ Tuyệt đối (1 phép tính) $O(1)$ Trung bình (Có thể đụng độ) $O(\log |\Sigma|)$ Binary Search
RAM Chi Phí Mỗi Nút Rỗng 208 Bytes (Lãng phí 95%) ~24–32 Bytes base overhead 0–24 Bytes (Tùy capacity)
Phạm Vi Ứng Dụng Từ điển Anh nhỏ (a-z) Từ điển Đa ngôn ngữ / Unicode Bộ từ khổng lồ tối ưu RAM
KHUYÊN DÙNG SẢN PHẨM THỰC TẾ: Trong các ứng dụng thương mại (Search Engine, Autocomplete Tiếng Việt), Hash Map (unordered_map) hoặc Sorted Vector luôn là ưu tiên hàng đầu để tránh tình trạng sụp đổ bộ nhớ RAM khi chứa hàng trăm nghìn từ khóa!
Slide 10 phân tích chi tiết sự đánh đổi Child Container giữa Mảng cố định, Hash Map và Vector. Mảng cố định cho tốc độ O(1) tuyệt đối nhưng lãng phí 208 bytes mỗi nút. Trong sản phẩm thực tế, Hash Map hoặc Vector là lựa chọn tối ưu bộ nhớ hơn.
